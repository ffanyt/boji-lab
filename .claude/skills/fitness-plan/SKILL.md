# 生成训练与饮食计划

数据结构、`bin/lsj` 用法和写入规则见项目根目录的 `CLAUDE.md` 和 `docs/data-model.md`。所有命令在项目根目录下运行。无人值守运行（`/fitness-review auto`）时不跑这个流程写计划，只按第 2、3 步算出新计划做成提案（见 `fitness-review` 的「自动运行」）。

先读这个人的 `meta/memory`（`bin/lsj get meta memory -u <用户名>`，不存在就跳过）：你记得的他的作息、饮食习惯、哪些动作做着不舒服，做计划时都要照顾到。

计划是每个账号各自的。先确认给谁做：用户点了名就用那个人；没点名时运行 `bin/lsj users`，只有一个账号就是他，有多个账号就问是给谁（或者对所有"资料已更新"的账号分别做）。下面所有命令都带 `-u <用户名>`。

## 1. 读取

- `bin/lsj get profile main -u <用户名>`、`bin/lsj get plan current -u <用户名>`（不存在会报错退出，正常）
- 连了训记的（`bin/xunji accounts` 里有这个人）：先 `bin/xunji sync -u <用户名> --days 90` 导入近 3 个月训练，再用 `bin/lsj list workouts --order date --desc --limit 60 -u <用户名>` 看他实际怎么练：分化方式、每周几练、每个动作的工作重量和次数、做到哪一组开始掉次数。同时读 `bin/lsj get meta xunji -u <用户名>`，看 `templates` 是不是 `"declined"`
- 有历史记录时：`bin/lsj range <21 天前> <当前日期> -u <用户名>`，看体重趋势、训练重量、喝水，以及已分析餐食的实际摄入（作为起点）；还要看 `sleep` 里他一般几点睡、几点醒

看旧计划的 `custom`：用户在页面上自己改过哪些（目标、训练日、快捷清单、周安排、轮换）。这些是他明确想要的，重做时要照顾到（见第 4 步）。`profile.targetWeight` 是他想到的体重，有的话按它说清楚节奏。

基础信息不存在或缺了关键项（目标、身高体重、每周天数）时，让用户先在手机上「我的 → 基础信息」填好，或者直接在对话里告诉你。在对话里拿到的信息也要写进 `profile/main`（字段见 `docs/data-model.md`）。

## 2. 饮食目标

1. 基础代谢用 Mifflin-St Jeor：男 `10×体重 + 6.25×身高 − 5×年龄 + 5`，女 `… − 161`
2. 维持热量 = 基础代谢 × 活动系数：每周练 1 天取 1.3，2–3 天取 1.4，4–5 天取 1.55，6–7 天取 1.65；伏案工作再减 0.05
3. 按目标调整，得到**每日平均**热量目标：减脂 −15～20%，增肌 +5～10%，减脂增肌 −5～10%，薄肌（`lean`）−5%～维持（看着体脂偏高、肚子明显的取 −10%），力量和健康取维持
4. 蛋白质 1.6–2.2 g/kg（减脂、薄肌取高值），脂肪 0.7–1.0 g/kg（薄肌 0.7–0.9），剩下的给碳水
5. 休息日：碳水减 20–30%，热量同步下调，写进 `restDay`。一周的平均要等于第 3 步的目标：（训练日热量 × 训练天数 + 休息日热量 × 休息天数）÷ 7 = 第 3 步的目标，所以休息日减下来的要加回训练日（加在碳水上）
6. 喝水目标 `water`（ml）：体重 × 35，训练日多出汗的再加 300–500，取整到 100
7. 有两周以上完整的实际摄入和称重数据时，用 `/fitness-review` 第 5 步「体重和热量」那条规则估实际维持热量，以它为起点，每次最多调 300 kcal，不要从头算
8. `guidelines` 3–5 条，要结合基础信息里的饮食习惯（吃食堂、点外卖、忌口）
9. `meals` 按他真实的作息排：从他醒来的时间到睡觉的时间安排几餐（看 `sleep` 的入睡、醒来时间和 `profile.notes`），用常见、容易买到的食物。睡得晚、深夜要吃东西的，把夜宵当成正经的一餐来安排（定好吃什么、多少），不要只写"尽量不吃夜宵"
10. `quick`：4–6 个快速补蛋白或深夜能吃的选择，`{name, kcal, protein, carbs, fat, when: any|late}`，从他实际会买的东西里挑（看已点评餐食的 `items` 和 `meta/foods`），适合深夜吃的标 `late`

## 3. 训练计划

- 分化：每周 1 天练一次全身（复合动作为主）；2–3 天练全身（A/B 或 A/B/C）；4 天上下肢分化；5–6 天推拉腿；7 天按推拉腿排 6 天，第 7 天写成轻松的有氧或活动恢复（`note` 里说明，不排力量）
- **薄肌**（`goal: "lean"`，体脂低、有线条、不追求大块）：力量训练照常是主体，复合动作打底，多给肩（侧平举、推肩）、背（下拉、划船）、手臂和核心一些组数，练出肩宽腰窄的轮廓；次数 8–15、每组做到接近力竭（RPE 8–9），照样渐进加重——"轻重量高次数才出线条"是误区，`summary` 或计划说明里说一句。每周再排 2–3 次 20–30 分钟有氧（快走、爬坡、骑车都行，写进 `training.note`），或者每天 8000 步以上。饮食 `guidelines` 结合「五件套」写（大水：每天 2 升白水代替饮料；大睡：睡够 8 小时；大蛋：每天 2–3 个蛋补蛋白质；大站：别久坐）。`phase` 写清楚这个阶段看什么：体重稳住或每周最多降 0.5%，腰围往下，训练重量往上
- 每次时长按 `minutes` 控制（用户填多少就按多少，30 分钟以内的只排 3–4 个动作、多用超级组）：每组按 2–3 分钟（含休息）估算，热身另算 10 分钟
- 器械按 `place` 选：健身房用杠铃和器械；家里用哑铃和弹力带；徒手用自重变式
- 新手：每个训练日 4–5 个动作，复合动作 3×8–10，RPE 7；有基础的上量到 5–6 个动作，主项 4×5–8；进阶的加入强度周期
- 避开 `injuries` 里提到的问题，换成替代动作，并在 `cue` 或 `note` 里说明
- `load`：有历史重量时写具体 kg，否则写 RPE。停练 4 周以上回来的，重量比停练前降 10–15%
- 每个动作给一句 `cue`（最关键的动作要点）
- 每个训练日的 `id` 用一个字母（A/B/C…，只在数据里用），`name` 按部位起（「胸 肩 三头」「背 二头」），再给一个 `short`（≤ 4 字的简称：「胸」「背」「腿」「上肢」）：页面上徽标、标题、chip 显示的都是简称，字母用户基本看不到。重做计划时同一个部位的日子保留原来的 `id`（`days/<日期>.plan`、`dayMap`、训练记录的 `planDayId` 都靠它）
- `schedule` 让训练日之间尽量隔开，避开 `notes` 里提到的固定忙碌日
- 训练记录显示他按固定顺序轮着练时（计划日总是 A→B→C→D 这样接着来，错过一天也不跳）：写 `rotation: ["A", "B", "C", "D"]`。这时 `schedule` 只决定哪几天练，练哪天由轮换决定（规则见 `CLAUDE.md` 的「口径」）
- `phase` 写清阶段和起止日期，一般 4 周一个阶段；同时写 `phaseInfo: {name, start, end, focus, deload?: {start, end}, next?}`（「训练」页的阶段进度条按它画：`focus` 一句话说这个阶段主要练什么、看什么指标，`next` 一句话说下个阶段大概做什么）。上一阶段连续练满了 4 周以上的，新阶段先排一周减量（组数减半、最少 2 组，重量不变，每组留 3–4 次余力）；中间停过练的直接开始
- 连了训记的：在他现有分化的基础上调整，不要推倒重来；动作名用训记官方名（`bin/xunji movements <关键词>` 查），和他训练记录里的写法保持一致

## 4. 写回

在 scratchpad 写一个 batch 文件 `<用户名>-<时间>.json`，内容是 `{"user": "<用户名>", "ops": [...]}`，用 `bin/lsj batch <文件> -u <用户名>` 一次提交：
1. 已有计划的：把旧计划的 `data` 原样 `set` 到 `plan_history/<当前日期>-v<version>`
2. `set plan/current`：`version`（新建为 1，否则 +1），`updatedAt`，以及 `docs/data-model.md` 里的全部字段；已存在时带 `ifVersion`。旧计划有 `custom` 时：
   - 用户在对话里明确让你把某些地方改回建议值（"热量按你算的来"、"训练日你重新排"）：这些路径用新算的值，从 `custom` 里删掉
   - 其余 `custom` 路径保留用户的值，把新算出的建议值写进 `custom[路径].was`（页面上「恢复建议值」就会恢复成新的建议），`at` 不变
   - 分化变了、用户改过的训练日（`training.days.<id>`）在新计划里对不上了：先用新的，在计划说明里写清楚他之前改了什么、新计划里怎么处理的，并在 `actions` 里请他看一眼
   - 计划说明的 `sections` 里加一节「你改过的」，列出保留了哪些、哪些改回了建议值
3. `update profile/main`：`{"needsReview": false}`，带 `ifVersion`
4. `set reports/plan-<当前日期>-v<version>`：kind `plan`，`title` 不超过 16 个字；说明热量和三大营养素是怎么算出来的（训练日、休息日、一周平均三个数放 `stats`）、为什么这样分化，以及开始执行的 3 条 `actions`，`createdAt` 为现在。不写"今天 / 明天"，写具体日期
5. `set log/<id>`：`{"at": 现在, "kind": "plan", "text": "按新资料重做了计划（第 <version> 版）"}`
6. 这次是因为用户留言要求的，同时回复那条留言（见 `fitness-review` 第 1.5 步）

然后在对话里用几行概括计划，提醒用户在手机上「训练」页查看（饮食目标在「今日 → 摄入 → 目标」），并告诉他训练日、目标、快捷清单都可以自己改。

**用户自己从模版搭的计划**（`plan.template: {name, at, keep}` 有、`diet` 是空的）：`keep: true`（默认；`custom` 里有全部 `training.days.<id>`、`training.schedule`、`training.rotation`）是他明确要的训练安排，训练部分原样保留（`custom` 照旧，`was` 写你会建议的那一天，页面上「恢复建议值」就能换成你的），觉得该改的写进计划说明的 `actions` 和日报里或做成提案，不直接改；`keep: false`（新手，`custom` 里没有这些）时保留他选的分化、天数和 `schedule`，动作、组数、次数、重量可以按资料和伤病调整，在计划说明里逐条写清楚改了什么。两种情况都做第 2 步的饮食目标写进 `diet`（这是第一次有饮食目标，不算改他的），`phase` / `phaseInfo` 按他搭的日期保留，`template` 字段原样带上，`version` +1、`plan_history`、计划说明照第 4 步

**新朋友的第一份计划**（刚用邀请码注册、没有历史记录）：照上面做，但没有历史重量时 `load` 一律写 RPE，第一周的 `actions` 写成上手指南：怎么记一餐（拍照、吃完点「吃完了」或拍剩的）、怎么开始训练、Claude 什么时候会看（每天两次），三条就够。计划说明的 `summary` 第一句欢迎他，按他选的人设说

## 5. 写进训记（连了训记的账号）

`meta/xunji.templates` 是 `"declined"` 的（用户说过不要），或者这个人只在薄肌研究所里记训练（`bin/lsj pending -u <用户名>` 的 `trainIn` 是 `"app"`），跳过这一步，不要再提议。

用户在训记里练，所以把每个训练日做成训记「Agent 模版」，他打开训记就能直接按模版开练，训记还会按递增规则自动加次数和重量。「训练」页上每个训练日都显示它在训记里的模版状态（`meta/xunji.templatesState`），计划改了、训记里还是旧的会标出来。

什么时候做：新计划写好后；训练部分改了（直接改的或用户同意的提案）、`templatesState` 里这天的 `planUpdatedAt` 比计划的 `updatedAt` 旧；用户交代了（留言 `kind: "xunji-templates"`、或说"写进训记"）。

怎么让用户确认（训记的规矩：写之前要用户看过改动、明确同意）：
- **网页上同意**（默认）：准备好 mutation 文件后用 `--propose` 出一个提案，用户在 Claude 页（右上角 ✦）或今日页看到每个模版的内容，点「写进训记」服务器马上提交。`meta/xunji.keys.template` 不是 true（服务器上没存模版 key）时照样出提案，同时在计划说明或日报的 `actions` 里提醒他去「我的 → 训记」存模版 key
- **对话里同意**：用户就在对话里时，也可以把预览摘要发给他，他明确说可以再 `--confirmed` 提交（用这台电脑上的模版 key），提交后在 `meta/xunji.templatesState` 记上（见第 4 条）

1. `bin/xunji templates -u <用户名>` 读当前 Agent 文件夹：已有哪些模版（`template_id`、`base_version`）、文件夹版本、容量
2. 在 scratchpad 写 mutation 文件：
   ```json
   {"upserts": [{"client_id": "lsj-chest-v1", "name": "胸 三头", "color": "#1D4ED8",
     "movements": [{"name": "哑铃卧推", "sets": [{"weight": 22.5, "reps": 10, "unit": "kg"}, …],
       "progression": {"start_reps": 8, "reps_increment": 1, "target_reps": 12, "weight_increment": 2.5, "reset_reps": 8}}]}],
    "deletes": []}
   ```
   - 新建用稳定的 `client_id`；更新已有模版带 `template_id` 和最新 `base_version`
   - 递增用双重递增：先加次数，所有工作组到 `target_reps` 后加重量并回到 `reset_reps`；上肢加 2.5kg，下肢加 5kg
   - 模版名只能用中文、英文字母、数字和空格（不能有「·」「（）」之类的符号），最多 14 个模版、每个 15 个动作、每个动作 20 组
   - 模版名用计划日的名字（「胸肩三头」「背二头」），每个模版的第一组重量用计划的 `load` 或最近一次 `nextByExercise`，次数用区间下限
3. `bin/xunji templates-mutate <文件> -u <用户名>` 预览，它会检查限制和动作名（官方动作名只有这里查，服务器提交时不再查）。有问题就改文件再预览
4. 出提案：`bin/xunji templates-mutate <文件> -u <用户名> --propose --title "把计划写进训记（4 个模版）" --why "…" --days '{"lsj-A": "A", "lsj-B": "B"}'`。`--days` 写每个模版（`client_id` 或 `template_id`）对应计划哪天，服务器写成功后据此更新 `templatesState`。同一个人已有 `open` 的训记提案会被改成 `stale`。再写一条 `log`（`kind: "xunji"`，"准备了 4 个训记模版，等你确认"）。对话里同意、用 `--confirmed` 提交的，自己 merge 写 `meta/xunji.templatesState`：`{"<计划日 id>": {"name": …, "at": 现在, "planUpdatedAt": <计划的 updatedAt>}}`
5. 用户在网页上点「不要」（`inbox` 状态 `declined`）：这次的不再提；说"以后都别写训记"的（留言里），在他的 `meta/xunji` 里写 `templates: "declined"`，以后不再提
6. 不要修改 Agent 文件夹以外的任何东西，不要删用户没让删的模版
